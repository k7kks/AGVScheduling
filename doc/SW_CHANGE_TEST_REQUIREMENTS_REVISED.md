# 软件代码修改及测试需求文档（修订版）

## 1. 目标与范围
- 目标：对外 path/traffic/trail 响应的校验与行为一致化，并补齐版本化发送与日志一致性要求。
- 范围：对外响应接口、轨迹发送策略、日志输出与落盘行为。

## 2. 对外响应接口范围
需检查并修改以下 3 个对外响应接口：
- path 接口（RobotPathResponse，对应 `build_path_response_body`）
- traffic 专属 path 接口（TrafficPathPublisher 的 payload，对应 `build_traffic_path_payload`）
- trail 接口（RobotTrailResponse，对应 `build_trail_response_body`）

## 3. 接口参数校验与行为要求
### 3.1 path 接口（RobotPathResponse）
要求：
- 返回结果不得为单点、空值、两个相同点。
- 若原始规划路径为无效结果，必须构造最小合法路径或返回明确错误（不得返回非法路径）。

建议实现要点：
- 对每段 `pathPoints` 做合法性校验：长度 >= 2，且任意相邻点 `nodeId` 不相同。
- 若 `pathPoints` 仅有 1 点或空：尝试补一个相邻可达节点（优先邻接边）；仍失败则返回 `code != 200` 且 `pathInfos` 为空。

### 3.2 traffic 专属 path 接口
要求：
- 返回结果不得为单点、空值、两个相同点。
- 路径不得存在碰撞。
- 逻辑与 trail 接口响应一致，仅数据格式不同。

建议实现要点：
- 使用与 trail 一致的“不可回撤前缀 + 追加”逻辑输出窗口（仅格式差异）。
- “不得存在碰撞”的判定需基于统一规则（建议以当前保留/占用节点为准），对输出窗口做过滤或重算；无法满足时返回错误或最小安全路径。
- 对窗口裁剪后若变为无效路径（空/单点/重复点），应触发重算或降级处理，确保不返回非法数据。

### 3.3 trail 接口（RobotTrailResponse）
要求：
- 返回结果不得为单点、空值、两个相同点。
- 发送的轨迹必须强制执行，不支持轨迹撤回操作（仅允许在尾部追加）。

建议实现要点：
- 轨迹生成逻辑必须保证“前缀不可回撤”，已下发轨迹不得被替换为更短路径。
- 若当前规划无法生成合法轨迹，允许“停留点 + 邻接点”作为最小轨迹；无法构造时返回错误或跳过响应（但不得返回非法轨迹）。

## 4. trail 接口版本差异化发送规则
### 4.1 版本类型与触发条件
- V1 版本：
  1) 任务分配完成后发送 1 次
  2) 重规划路径后发送 1 次
- V2、V100 版本：
  1) 周期性发送
  2) 重规划路径后额外发送 1 次

### 4.2 版本识别与配置（待确认）
- 版本来源：建议来自配置/环境变量或控制端请求标识。
- 周期性发送频率：需新增或复用配置项（如 `TRAIL_PUBLISH_INTERVAL_MS`）。

## 5. 日志（log）功能修改需求
1) status 日志默认配置：保持 status 日志默认不保存的规则。
2) 日志一致性：控制端终端显示的日志内容需与本地保存的日志文件内容完全一致。

建议实现要点：
- 统一日志输出路径：同一日志内容同时写终端与文件，避免“部分字段仅终端/仅文件”。
- 若支持日志级别或开关，需确保终端与文件遵循同一开关与格式。

## 6. 测试需求与验收标准
### 6.1 接口合法性测试
覆盖对象：path / traffic / trail 三类响应。
必测场景：
- 空路径：输入或规划结果为空时，响应必须为“错误 + 空 pathInfos”，或可构造合法最小路径。
- 单点路径：返回不得为单点；应补齐到合法两点或错误返回。
- 两相同点：路径为 `[n, n]` 时需去重或补齐，确保相邻点不相同。

验收标准：
- 任意接口不返回空/单点/两相同点的路径数据。

### 6.2 traffic 路径碰撞测试
必测场景：
- 目标路径与他车保留节点冲突时，输出需规避冲突。
- 保留窗口长度变化时，结果仍不产生冲突。

验收标准：
- traffic 输出的路径窗口内不存在与其它车辆保留/占用节点冲突的点。

### 6.3 trail 不可回撤测试
必测场景：
- 已下发的 trail 前缀在下一次响应中不得减少或被替换。
- 轨迹重规划仅允许在尾部追加或延展。

验收标准：
- trail 前缀保持一致，且无回撤。

### 6.4 版本化发送测试
必测场景：
- V1：任务分配后发送一次；重规划后发送一次；无周期性发送。
- V2/V100：按周期发送；重规划时额外发送一次。

验收标准：
- 发送频率与触发条件符合版本规则。

### 6.5 日志一致性测试
必测场景：
- 同一操作在终端与文件日志的输出内容一致。
- status 日志默认不落盘。

验收标准：
- 终端与文件日志逐行一致（忽略时间戳差异需先明确格式）。
